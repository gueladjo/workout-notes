# Architecture

WorkoutNotes is a single-page application built with React 19, TypeScript and Vite, shipped as a
Progressive Web App. Its one non-obvious decision is the storage model: **the app's database is a
FitNotes backup file**.

## Storage model: SQLite is the canonical store

A FitNotes `.fitnotes` backup is a plain SQLite database (see [fitnotes-format.md](fitnotes-format.md)).
Instead of defining an internal schema and writing importers/exporters, WorkoutNotes opens the
SQLite file in the browser with [sql.js](https://sql.js.org) (SQLite compiled to WebAssembly) and
uses it directly:

- **Restore** = validate the file, reconcile the schema (`ensureSchema`), swap it in.
- **Export** = hand out the live database bytes.
- **Fresh install** = create a database with FitNotes' own `CREATE TABLE` statements and defaults.

Consequences:

- Round-trip fidelity is byte-exact; there is no mapping layer to drift.
- Every query is SQL against FitNotes' tables (`training_log`, `exercise`, ...), which suits the
  aggregate-heavy screens (history, graphs, records, calendar).
- The whole database lives in memory (a decade of training is a few MB) and is written back to
  IndexedDB as one blob after changes (debounced, plus on page hide). See [storage.md](storage.md).

The alternative (an internal IndexedDB schema plus SQLite import/export) was rejected because the
primary requirement is FitNotes compatibility and a second schema doubles the surface for bugs.

## Layers

```
src/
  db/
    sqlite.ts        sql.js loading + tiny query helpers (Node and browser)
    schema.ts        FitNotes DDL, ensureSchema(), createEmptyDatabase(), backup validation
    constants.ts     integer encodings (exercise types, units, goal types, ...) and DB version
    seed.ts          default categories/exercises/measurement units/measurements
    types.ts         camelCase row interfaces used above the repositories
    store.ts         AppDatabase: the live db, mutate() transactions, change notification, persist
    persistence.ts   IndexedDB blob store (live db + rollback snapshots), storage persistence API
    repo/            one module per concept; the only place SQL is written
  domain/            pure functions: units, dates, records (Brzycki/PRs), graphs, stats, colours
  backup/            restore/export of .fitnotes, CSV export, file download/share helpers
  app/               bootstrap (open db), React contexts/hooks, routes, return-to protocol
  ui/
    components/      TopBar, Menu, Dialog, Tabs, NumberField, MonthGrid, LineChart, ...
    screens/         one file per screen (Home, ExerciseList, Training, Calendar, Routines, ...)
    styles.css       design tokens (light/dark) and every component style
```

Dependency direction: `ui -> app -> db/repo -> db/store -> db/sqlite`, with `domain` usable from
anywhere. `db/*` has no browser-only imports so unit tests and scripts run in Node.

### Reading and writing

- Screens call `useQuery((db) => repo.fn(db, ...), deps)`. The hook re-runs the query when the
  database version changes (every mutation increments it) or when `deps` change.
- Writes go through repository functions which wrap their SQL in `db.mutate()`. Nested mutations
  join the outer transaction; only the outermost notifies subscribers and schedules persistence.
- Personal-record flags are recomputed per exercise after each set change (`repo/records.ts`),
  mirroring FitNotes which stores `is_personal_record` on rows.

### Routing

`react-router` with a hash history (`/#/workout/2026-09-12`), so the built site works from any
static path without rewrite rules and the installed PWA handles the back button natively.
Routes are listed in `src/app/App.tsx`; the screen map is in [ui.md](ui.md).

### PWA

`vite-plugin-pwa` generates the manifest and a Workbox service worker that precaches the app shell
including the ~650 KB SQLite WASM. `registerType: 'autoUpdate'` refreshes the worker in the
background; a new version is used on the next launch. Icons are generated by `scripts/make-icons.ts`.

## Cross-cutting rules

- Storage units are metric (kg, metres, seconds). `domain/units.ts` converts for display using the
  exercise's weight unit (`exercise.weight_unit_id`) or the Unit System setting, and the set's
  distance unit (`training_log.unit`).
- Settings are a single row in FitNotes' `settings` table (`repo/settings.ts`) so they travel with
  backups; the only browser-local state is the "last backup" timestamp.
- Dates are local calendar dates as `YYYY-MM-DD` text; never converted through UTC.
